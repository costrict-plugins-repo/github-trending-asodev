# What's New and Release Notes

Write clear release notes.

## Inputs

- Version
- Release date
- New features
- Improvements
- Bug fixes
- User impact
- Tone
- Countries/locales

## Output

```md
# What's New

## Recommended
...

Characters: ...

## Short version
...

## More detailed version
...

## Localization notes
-
```

## Rules

* Lead with user benefit.
* Do not overstate bug fixes.
* Keep it human and specific.
* Avoid "minor fixes" only when there are real improvements.
